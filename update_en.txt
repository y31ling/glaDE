V0.4.5

- Added macOS deployment support (Apple Silicon and Intel).
  ⚠️ IMPORTANT: the macOS support in this release has NOT yet been compiled or run on a real Mac; it was only verified on Linux to not break existing behavior. On first use on a Mac, rely on the `import glafic` self-check at the end of bootstrap_macos.sh, and please report any build/link issues so the Makefile can be tuned.
  - New one-click installer bootstrap_macos.sh: installs cfitsio / fftw / gsl via Homebrew (no source build), auto-adapts to Apple Silicon (/opt/homebrew) and Intel (/usr/local) via brew --prefix, writes a macOS glafic Makefile (cc + -bundle -undefined dynamic_lookup, no libpython link, no OpenMP), builds the glafic binary and Python extension, sets up the venv / installs deps, registers the .pth, and generates env.sh / run_glade.sh / run_webui.sh.
  - DE and MCMC multiprocessing is now platform-aware (new core/parallel.py): Linux stays on fork (byte-identical behavior) and macOS switches to spawn -- forking after the Accelerate BLAS and glafic extension are loaded triggers macOS's fork-safety abort. Because the optimization objective / likelihood objects are already picklable and rebuild the glafic engine lazily per worker, spawn is result-identical to fork; DE uses a fixed seed with updating=deferred and emcee's RNG lives in the parent, so parallel results are unchanged. DE_WORKERS / MCMC_WORKERS (-1 = all cores) are honored as before.
  - WebUI job execution gained a macOS branch: on macOS it opens a real Terminal.app window to run the job (matching the Linux gnome-terminal experience); the Linux path is untouched.
- No impact on Linux: the core test suite passes 81/81 and Linux multiprocessing remains fork; all macOS-specific branches are isolated behind a platform check.
- GPU is optional on macOS: with no CUDA it falls back to CPU (no crash); Apple Metal / MPS is not yet wired up.


V0.4.4

- Added extended-source (FITS image) fitting: a .dat can now reference an observed FITS image and several external file addresses (extended_file / extend_mask_file / noise_file / constraint_file / prior_file), letting glafic fit extended sources (Sersic etc.) pixel-by-pixel on the CPU; the extended-source optimization path is auto-detected and switched to at run time.
  - Added five extended-source component types extsersic / extgauss / exttophat / extmoffat / extjaffe (category=extend, CPU/glafic-only); the tuple z is the source redshift and the params are (norm, x, y, e, pa, size, index), each mapping to a glafic set_extend keyword.
  - In extend mode glafic solves the SN point-source position internally, so source_x/source_y are no longer outer DE dimensions; point-source constraints may be given either as a glafic-native constraint_file (full fidelity) or as glade obs arrays (converted at build time to a temporary glafic constraint file).
  - Added a weightable per-component loss: the bundled glafic C engine gained chi2tot_each(), which splits the total chi2 into 8 components (position, flux, time-delay, point-param prior, extended pixel, extended-param prior, lens+map prior, range penalty), exposed all the way to Python via c2calc_each; new .dat weight keys W_POS / W_FLUX / W_TD / W_EXT / W_PRIOR (all default 1.0, in which case the loss equals glafic's native c2calc exactly).
  - Extended-source fitting now supports MCMC (mcmc and de+mcmc modes) with likelihood -0.5 x weighted c2calc loss, consistent with the DE result; it honors MCMC_WORKERS via a fork-based CPU process pool and adds an initial-walker feasibility check: if every walker lands at zero likelihood it raises an actionable error (use de+mcmc or narrow the ranges), and otherwise infeasible walkers are jittered/replaced. Note: extend MCMC is slow (one glafic call per walker per step) -- use a modest MCMC_NSTEPS.
  - Added an extended-source result triptych (observed / best-fit model / residual) with optional critical-curve and image-position overlays; degrades to a model-only single panel when the observed FITS is unavailable.
  - Added independent verification verify_extend: it re-solves with the standalone glafic binary (start_setopt + c2calc + findimg) and compares against glade's summed c2calc (warns if the relative difference is >5%), plus an engine-independent scipy source-plane reference check; gated by glafic_verified.
  - Extended-source fitting is CPU-only for now: selecting a GPU backend for an extend config is clearly rejected (validate() emits gpu_unsupported).
- Added a graded missing-image penalty missing_img_penalty (default 0.0 = the historical hard-reject): when a candidate forms fewer images than observed it is no longer discarded but scored on its available-image / extended-pixel chi2 plus (n_obs - n_pred) x penalty; it applies consistently across the point, batched-GPU, and extend paths (the upper-case alias MISSING_IMG_PENALTY is also accepted).
- The WebUI and the translate/import path gained extended-source support:
  - The template tree adds an Extend Source component category (the five extend models, using source_z and noting that extended_file is required), enables the previously disabled Extend_images obs-data snippet, adds a DE-Extend (CPU) algorithm template (exposing the five c2calc weights, missing_img_penalty, glafic_verified, etc.), and adds missing_img_penalty to the DE-CPU / DE-GPU snippets.
  - The run-check confirm dialog now recognizes extend configs (reports mode 'extend' and the correct dimension count); an extend run produces the result.png triptych, iteration frames, a best_params.txt with the 8 chi2 components, MCMC plots/summary, and an independent-verification block.
  - glafic -> glade import now also parses python driver scripts (import glafic; glafic.*(...)): a script with set_extend / readobs_extend imports into a full extend-mode .dat (deflectors plus extsersic/extgauss components, file paths reduced to basenames, optimizable params rendered as degenerate {v, v} bounds, and set_secondary hvary 1 making hubble an optimizable bounds).
- Added an optimizable Hubble constant: when hubble/H0 is given as {lo, hi} bounds (e.g. time-delay cosmography) it becomes a DE dimension and is reported in the fitted results.
- Under-the-hood refactor (behavior unchanged): extracted a shared point_source_loss() scoring function used identically by the CPU, batched-GPU, and MCMC paths; matching gained assign_images() (Hungarian match supporting n_pred <= n_obs) so the missing-image penalty behaves the same on every path; the new c2calc_each C change is purely additive and alters no existing function signature or behavior.
- Added test suite core/tests/test_extend.py (22 tests, all passing) covering extended-source / FITS fitting end-to-end (schema registration, extend-mode validation, dimension routing, the weighted loss and its parity with c2calc, point-constraint-file read/write, python-script import, the graded missing-image penalty, and live glafic-engine checks); test_optimize.py adds 3 point-path missing-penalty tests.


V0.4.3

- Synced the bundled glafic to upstream v2.1.14 (was v2.1.10), absorbing all four upstream releases:
  - 2.1.11: fixed a typo in the crline (straight critical line, model #24) y-deflection.
  - 2.1.12 / 2.1.13: the azimuthal kappa-average integral switched from adaptive Romberg to Gauss-Kronrod (gsl_qgaus2), more robust (affects kapparad/kappacum etc., which GLADE does not use directly).
  - 2.1.13: a new relrange (relative-range) prior for parprior.
  - 2.1.14: a new acnfw lens model (approximate cored-NFW via a CSE series), with a new file app_cnfw.c.
- Preserved all of GLADE's local glafic modifications:
  - The King (1962) lens model -- because upstream's acnfw took model number 26, King was renumbered to model number 27 (still selected by the name "king", so input files and core/ need no change).
  - TOL_ROMBERG_JHK kept at 1.0e-5 (upstream is 5.0e-4).
  - The vendored-dependency build (app_cnfw.o added to both the Makefile and bootstrap_linux.sh).
- Verification: the rebuilt binary, static library, and python module all build cleanly; the King model produces bit-identical results before and after the upgrade via both the CPU binary and the python interface (point_solve); acnfw solves correctly; King and acnfw coexist without collision.
- While syncing, found and reported two upstream glafic bugs (unrelated to GLADE and not triggered by it): an extended-source-optimize segfault when a prior rejects the initial model (oguri/glafic2#4), and the relrange psf prior reading uninitialized variables (oguri/glafic2#5). See glafic_relrange_psf_bug_report.md and glafic_upstream_issue_draft.md.


V0.4.2

- The GPU result figure now uses the batched solver's images (the same engine that drove the optimization) instead of re-rendering with glafic, so a GPU run's figure matches exactly what the optimizer saw.
- New parameter glafic_verified (default True): after each run, independently invoke the glafic binary on the best-fit model and compare its loss/images to the optimizer's. This is purely a check; it never affects the result figure and the run always completes, only warning when the discrepancy is large. Set it to False to disable.
- Added a scipy-exact reference verification (ground truth): independent analysis confirmed Rhongomyniad (GPU) Sersic deflection matches a scipy@1e-12 integral to about 1e-9 arcsec, while glafic's Sersic is Romberg-tolerance-limited (TOL_ROMBERG_JHK, kept at 1e-5 here: fast but not accurate enough at roughly micro-arcsec to milli-arcsec scales). Verification now reports both the glafic binary (informational) and the scipy-exact reference (run-engine Sersic deflection error plus source-plane self-consistency). Saved results now use 10 significant figures.


V0.4.1

- GPU batching: DE-GPU and GPU MCMC now solve each whole population/generation in one CUDA batch, matching the legacy batched behavior.
- Added MCMC workflows:
  - The FindImage sidebar now has a fourth option, MCMC, for direct MCMC fitting without DE; priors are the parameter {lower, upper} bounds, mass-like parameters are sampled in log10 space, and corner plots do not show a DE red line.
  - On CPU/GPU, setting MCMC_ENABLED = True runs DE first and then MCMC seeded around the DE best fit; corner plots overlay the DE red line and the behavior is close to legacy. DE and MCMC share the same parameter space.
  - Removed MCMC_CUSTOM_RANGE / MCMC_SEARCH_RADIUS / MCMC_LOG_M_MIN / MCMC_LOG_M_MAX; MCMC priors are always the DE {lower, upper} bounds. Old .dat files containing these keys still load with warnings.
  - Output now includes corner plots, trace plots, posterior percentiles, and direct display in the WebUI result area; the Template panel now includes MCMC-GeneralConfig.
- Cleaned up a legacy runaway-process hazard.
- Reverted the glafic constant for speed: TOL_ROMBERG_JHK 1.0e-8 -> 1.0e-5.


V0.4.0 - ReUnit Major Update

- Core refactor: the previously scattered and duplicated Differential Evolution optimization and plotting code in legacy/ was extracted into a unified, backend-agnostic core/ module. legacy/ remains as a historical archive, while new code no longer depends on it.
  - core/optimize: a single DE optimizer can drive glafic (CPU) or Rhongomyniad (GPU); main lenses and substructures (point-mass / NFW / King / p-jaffe and more) can be composed and optimized together.
  - core/plot: unified triptych, critical-curve, and iteration-frame plotting.
  - core/format: a new .dat configuration format and parser.
  - core/translate: bidirectional glafic <-> GLADE translation scripts, including a CLI.
- New .dat configuration format: close to the legacy inline style, with {lower, upper} marking optimizable dimensions (bare values are locked) and $float / $int as fill-in placeholders; mass-like parameters are searched in log10 space. Multiple files merge by section, component indices are globally renumbered, and missing basic values fall back to defaults with confirmation.
- Fully rewritten WebUI (webui/; old web/ deprecated): top-level FindImage and Editor pages; FindImage selects CPU / GPU / Glafic plus one or more .dat files, opens a real terminal for each run, and streams output back through SSE into independent job directories to solve concurrency issues. The Editor is VSCode-like with a 50px icon rail, draggable sidebar, Monaco multi-tab editor, save/delete controls, Explorer management for InputFiles, import/export translation, and Template insertion at the cursor.
- glafic <-> GLADE translation: import converts optimization-matrix parameters marked as 1 into {v, v} bounds for manual adjustment; export writes representative values for bounds (geometric mean for mass-like parameters) and separates observation/model data.
- Fixes: center_offset_x in the DE objective now follows obs_x_flip so it stays in the same coordinate system as observations, fixing global predicted-image offsets and stuck losses; glafic TOL_ROMBERG_JHK is set to 1.0e-5 as a speed/accuracy compromise.
