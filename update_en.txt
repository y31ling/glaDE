V0.7.1 - fine_tuning staged optimization (macro -> substructure -> joint polish)

- New .dat key fine_tuning (absent = off by default):
  fine_tuning = (activate, algo1, A1, B1, algo2, A2, B2, algo3, perturb, A3, B3)
  with companion keys fine_tuning_top_k (diverse basins / chains, default 3) and
  fine_tuning_diversity (basin-diversity criterion: at least one dimension
  differs by >= diversity x that dimension's bound width, default 0.1).
- Round 1 removes every substructure component and globally searches only the
  user-optimizable macro (main lens + source) parameters; the top_k mutually
  diverse basins from the search history seed independent chains.
- Round 2 freezes each chain's macro (source position included) at its seed and
  optimizes only the substructure {lo, hi} parameters.
- Round 3 first prunes (a chain whose round-2 loss is an order of magnitude
  worse than the best is dropped), then re-opens EVERY lens / substructure /
  source parameter -- user-fixed or optimizable alike -- in a narrow
  value*(1 +- perturb) box and polishes jointly; the winner is the final
  result, and a runner-up within 2x of the winner is called out in the log
  (the data may not distinguish the two solutions).
- Per-round algorithms: DE / BIPOP-CMA-ES / jSO (amoeba is NOT supported --
  that is the glafic-binary rail); AN/BN override LOSS_COEF_A/B per round while
  budgets still come from the usual DE_*/CMAES_*/JSO_* keys. The lens vs
  substructure split uses the STRICT rule: an Nl/Ns index suffix wins, else the
  model's schema category (never the report-marker "optimizable => substructure"
  default -- that would delete the main lens in round 1).
- When an activation precondition fails (no main lens, no substructure, nothing
  to optimize in round 1 or 2, extended-source mode, or a shared {lo, hi}
  variable spanning both a lens and a substructure component) the run falls
  back to a normal single optimization with a warning.
- Deliberate semantics: redshifts and hubble keep their original optimizability
  in round 3 (a user-fixed z is a measurement and does not wander); an
  originally-fixed exact zero stays fixed while an originally-optimizable zero
  falls back to +- perturb x (hi - lo); shared variables remain ONE shared
  dimension (still shared after the round-3 narrowing); _unused parameter slots
  are skipped. With the substructure removed, the round-1 macro may form fewer
  images than observed -- if the hard reject empties round 1, consider
  missing_img_penalty > 0 or a round-1 B1 = 0 (see SPEC.md).
- Per-stage deliverables land in ft_round1/, ft_round2_chain<n>/,
  ft_round3_chain<n>/ under the run directory (best_params.txt + a reusable
  glade_output_*.dat, written BEFORE any glafic figure so a C-binding abort
  cannot lose them); status.json gains a fine_tuning summary (per-chain seed /
  round2 / round3 losses and prune flags); the winner then flows through the
  normal triptych / glafic-verify / MCMC machinery (the MCMC seed is re-mapped
  onto the user's ORIGINAL {lo, hi} bounds, so the prior is unchanged).
- WebUI: the Editor template tree (Algorithm parameters) gains a "Fine-tuning
  (staged)" snippet; no new mode is needed -- findimage / de+mcmc automatically
  take the staged pipeline when fine_tuning is active (the CLI --optimizer is
  ignored there; the .dat tuple decides each round).
- Safety hardening (landed after an adversarial review pass):
  - The round-3 box is intersected with the user's original {lo, hi} (for
    originally-optimizable parameters) and clamped to the engine's hard
    parameter domains (ellipticity e < 1, Sersic n in [0.06, 20], power-law
    gamma in (1, 3), ...) -- crossing those makes glafic exit() at the C level,
    killing the whole process; a box that collapses under clamping keeps the
    parameter fixed.
  - Round 3 can only IMPROVE a chain: the incumbent (box centre) is re-scored
    under the round-3 objective and kept whenever the polish fails to beat it
    (skipped chains get the same re-scoring, so all chains' final losses
    compare in the same units).
  - The winner's headline loss is re-expressed in the .dat's own LOSS_COEF_A/B
    convention (per-stage files keep each round's own), so status /
    best_params / triptych / glafic-verify read like a normal run.
  - The MCMC seed re-mapped onto the full problem is clipped into the user
    bounds (the round-3 box may lawfully poke past them, and an out-of-prior
    seed collapses the walker init).
  - select_diverse never pads the chains with INVALID_LOSS candidates; derived
    round configs pin the Nl/Ns classification (so the report never marks the
    main lens as a subhalo) and strip the fine_tuning keys (per-stage
    glade_output files are directly re-runnable single-stage inputs).
  - fine_tuning / fine_tuning_top_k / fine_tuning_diversity (and their UPPER
    aliases) are reserved names from this release on; an older .dat using them
    as custom variables must rename them (the error message says so). On the
    library path, glade.optimize() warns about an active fine_tuning key and
    points to the newly exported glade.run_fine_tuning().
- New tests: core/tests/test_fine_tuning.py (parsing / validation / partition /
  freezing / perturbation / pruning / domain clamping / no-regression guard /
  end-to-end / determinism, 22 cases).

V0.5.3 - arithmetic expressions + observed-image references in .dat parameters

Component parameters (and their {lo, hi} bounds) may now be arithmetic expressions that reference the observed image positions, evaluated automatically at load time:

    'king1': (4, 'king', lens_z, {1e2, 1e8},
              {img1_x-0.075, img1_x+0.075},
              {obs_positions_mas_list[0][1]-0.075, obs_positions_mas_list[0][1]+0.075},
              {0,0.9}, {0,180}, {0.00008, 0.0080}, {0.5, 2.5})

- Operators: + - * / ** and parentheses (e.g. (img1_x+img2_x)/2 = the midpoint between two images). Numeric-only arithmetic is folded immediately; anything referencing observations is resolved after all files are merged.
- Observed-image references:
  - imgN_x / imgN_y  -- the N-th observed image (1-based).
  - obs_positions_mas_list[i][j]  -- the same image, 0-based; j=0 -> x, j=1 -> y. img1_x is exactly obs_positions_mas_list[0][0], etc.
  - These are NOT the raw mas value: they are converted to the engine (glafic lens) frame the optimizer uses (core.optimize.scene.build_obs): milliarcsec -> arcsec, the obs_x_flip sign on x, and center_offset applied -- x = x_sign*(mas_x/1000 - center_offset_x), y = mas_y/1000 - center_offset_y. So a {img1_x-0.075, img1_x+0.075} box is a +/-0.075 ARCSEC search box centred on where image 1 actually appears, and a lens placed there sits under the image (verified end-to-end against the glafic binary: amoeba lands the king exactly on the image's engine-frame position). Arithmetic constants are therefore in arcsec, engine frame.
  - Other observation arrays (obs_magnifications_list[k], obs_pos_sigma_mas_list[k], ...) are also subscriptable but returned RAW (no frame/unit transform) -- only obs_positions_mas_list[i][0|1] / imgN_x|y carry the position transform.
- Works on every rail: the {lo, hi} expressions resolve to ordinary bounds before the optimizer sees them, so DE/MCMC (CPU/GPU), the glafic-amoeba export (start_setopt + parprior ranges), and the editor's live lint all handle them identically.
- Clear errors for an unknown name, an out-of-range image index, a reference used without observations, function calls (only +-*/** are allowed), and obs-position expressions placed in a scalar assignment (or nested in a list scalar) -- they are component-only.
- Hardened via a multi-agent adversarial review (4 issues found + fixed): expressions resolve in the SAME engine frame the optimizer uses even when center_offset/obs_x_flip are omitted from the .dat (they fall back to DEFAULTS, not 0/False -- the bug would otherwise have silently mis-placed the lens); `**` overflow / 0**-n surface as clean diagnostics instead of raw Python exceptions; malformed obs arrays and list-nested expressions are rejected with a proper error rather than crashing at fit time.

V0.5.2 - native glafic amoeba + optimize-ready export

Two improvements centered on glafic's native amoeba (simplex) optimizer:

- glade -> glafic export: when a .dat has any {lo,hi}, the exported .input is now optimize-ready instead of findimg-only -- a start_setopt matrix (one 1-flag per {lo,hi}), an optimize command, a readobs_point constraint file and a parprior range file, plus the glafic-required end_startup (which the old export omitted, so its output never actually ran).
  - Parameter mapping: braces -> setopt flag + parprior range (param_no 1 = z, 2..8 = p1..p7, linear bounds); source_x/source_y braces -> the point opt row; hubble braces -> hvary + range hubble.
  - Shared user variables (one {lo,hi} variable referenced by several components) are exported faithfully as a SINGLE search dimension via glafic's `match` directive (match lens i j ii jj 1.0 0.0 -- a hard 1:1 tie, no chi2 term), so glafic keeps the tied parameters exactly equal during the fit (verified against the binary: the free-dimension count drops and the tied values stay identical).
  - Observation constraints use glafic's readobs_point format (the glafic binary cannot read the old start_obs wrapper), converted to glafic's lens frame with GLADE's obs_x_flip + center_offset convention; magnifications are written as |mu| with the sign carried in the parity column.

- The WebUI "Glafic" backend now runs glafic's native amoeba (optimize) instead of GLADE's Differential Evolution:
  - glade .dat selections are converted to temp glafic files (model/obs/prior) in the job dir, then optimized; GLADE's DE/MCMC-only variables (DE_*, MCMC_*, ...) do not apply to amoeba and are naturally dropped.
  - native glafic .input selections run directly (the .input plus the files it loads are staged into the job dir, so glafic outputs no longer pollute InputFiles/); a mixed glade+glafic selection gives a clear message instead of a low-level parse error.
  - results parse glafic's chi^2 + predicted images and reuse the standard triptych; a non-zero glafic exit code is reported as a failed run.
  - 5 new translate/export tests; end-to-end verified against the real glafic binary.   - New one-click installer bootstrap_macos.sh: installs cfitsio / fftw / gsl via Homebrew (no source build), auto-adapts to Apple Silicon (/opt/homebrew) and Intel (/usr/local) via brew --prefix, writes a macOS glafic Makefile (cc + -bundle -undefined dynamic_lookup, no libpython link, no OpenMP), builds the glafic binary and Python extension, sets up the venv / installs deps, registers the .pth, and generates env.sh / run_glade.sh / run_webui.sh.
  - DE and MCMC multiprocessing is now platform-aware (new core/parallel.py): Linux stays on fork (byte-identical behavior) and macOS switches to spawn -- forking after the Accelerate BLAS and glafic extension are loaded triggers macOS's fork-safety abort. Because the optimization objective / likelihood objects are already picklable and rebuild the glafic engine lazily per worker, spawn is result-identical to fork; DE uses a fixed seed with updating=deferred and emcee's RNG lives in the parent, so parallel results are unchanged. DE_WORKERS / MCMC_WORKERS (-1 = all cores) are honored as before.
  - WebUI job execution gained a macOS branch: on macOS it opens a real Terminal.app window to run the job (matching the Linux gnome-terminal experience); the Linux path is untouched.
- No impact on Linux: the core test suite passes 81/81 and Linux multiprocessing remains fork; all macOS-specific branches are isolated behind a platform check.
- GPU is optional on macOS: with no CUDA it falls back to CPU (no crash); Apple Metal / MPS is not yet wired up.


V0.4.4

- Added extended-source (FITS image) fitting: a .dat can now reference an observed FITS image and several external file addresses (extended_file / extend_mask_file / noise_file / constraint_file / prior_file), letting glafic fit extended sources (Sersic etc.) pixel-by-pixel on the CPU; the extended-source optimization path is auto-detected and switched to at run time.
  - Added five extended-source component types extsersic / extgauss / exttophat / extmoffat / extjaffe (category=extend, CPU/glafic-only); the tuple z is the source redshift and the params are (norm, x, y, e, pa, size, index), each mapping to a glafic set_extend keyword.
  - In extend mode glafic solves the SN point-source position internally, so source_x/source_y are no longer outer DE dimensions; point-source constraints may be given either as a glafic-native constraint_file (full fidelity) or as glade obs arrays (converted at build time to a temporary glafic constraint file).
  - Added a weightable per-component loss: the bundled glafic C engine gained chi2tot_each(), which splits the total chi2 into 8 components (position, flux, time-delay, point-param prior, extended pixel, extended-param prior, lens+map prior, range penalty), exposed all the way to Python via c2calc_each; new .dat weight keys W_POS / W_FLUX / W_TD / W_EXT / W_PRIOR (all default 1.0, in which case the loss equals glafic's native c2calc exactly).
  - Extended-source fitting now supports MCMC (mcmc and de+mcmc modes) with likelihood -0.5 x weighted c2calc loss, consistent with the DE result; it honors MCMC_WORKERS via a fork-based CPU process pool and adds an initial-walker feasibility check: if every walker lands at zero likelihood it raises an actionable error (use de+mcmc or narrow the ranges), and otherwise infeasible walkers are jittered/replaced. Note: extend MCMC is slow (one glafic call per walker per step) -- use a modest MCMC_NSTEPS.
  - Added an extended-source result triptych (observed / best-fit model / residual) with optional critical-curve and image-position overlays; degrades to a model-only single panel when the observed FITS is unavailable.
  - Added independent verification verify_extend: it re-solves with the standalone glafic binary (start_setopt + c2calc + findimg) and compares against glade's summed c2calc (warns if the relative difference is >5%), plus an engine-independent scipy source-plane reference check; gated by glafic_verified.
  - Extended-source fitting is CPU-only for now: selecting a GPU backend for an extend config is clearly rejected (validate() emits gpu_unsupported).
- Added a graded missing-image penalty missing_img_penalty (default 0.0 = the historical hard-reject): when a candidate forms fewer images than observed it is no longer discarded but scored on its available-image / extended-pixel chi2 plus (n_obs - n_pred) x penalty; it applies consistently across the point, batched-GPU, and extend paths (the upper-case alias MISSING_IMG_PENALTY is also accepted).
- The WebUI and the translate/import path gained extended-source support:
  - The template tree adds an Extend Source component category (the five extend models, using source_z and noting that extended_file is required), enables the previously disabled Extend_images obs-data snippet, adds a DE-Extend (CPU) algorithm template (exposing the five c2calc weights, missing_img_penalty, glafic_verified, etc.), and adds missing_img_penalty to the DE-CPU / DE-GPU snippets.
  - The run-check confirm dialog now recognizes extend configs (reports mode 'extend' and the correct dimension count); an extend run produces the result.png triptych, iteration frames, a best_params.txt with the 8 chi2 components, MCMC plots/summary, and an independent-verification block.
  - glafic -> glade import now also parses python driver scripts (import glafic; glafic.*(...)): a script with set_extend / readobs_extend imports into a full extend-mode .dat (deflectors plus extsersic/extgauss components, file paths reduced to basenames, optimizable params rendered as degenerate {v, v} bounds, and set_secondary hvary 1 making hubble an optimizable bounds).
- Added an optimizable Hubble constant: when hubble/H0 is given as {lo, hi} bounds (e.g. time-delay cosmography) it becomes a DE dimension and is reported in the fitted results.
- Under-the-hood refactor (behavior unchanged): extracted a shared point_source_loss() scoring function used identically by the CPU, batched-GPU, and MCMC paths; matching gained assign_images() (Hungarian match supporting n_pred <= n_obs) so the missing-image penalty behaves the same on every path; the new c2calc_each C change is purely additive and alters no existing function signature or behavior.
- Added test suite core/tests/test_extend.py (22 tests, all passing) covering extended-source / FITS fitting end-to-end (schema registration, extend-mode validation, dimension routing, the weighted loss and its parity with c2calc, point-constraint-file read/write, python-script import, the graded missing-image penalty, and live glafic-engine checks); test_optimize.py adds 3 point-path missing-penalty tests.

V0.4.2

- The GPU result figure now uses the batched solver's images (the same engine that drove the optimization) instead of re-rendering with glafic, so a GPU run's figure matches exactly what the optimizer saw.
- New parameter glafic_verified (default True): after each run, independently invoke the glafic binary on the best-fit model and compare its loss/images to the optimizer's. This is purely a check; it never affects the result figure and the run always completes, only warning when the discrepancy is large. Set it to False to disable.
- Added a scipy-exact reference verification (ground truth): independent analysis confirmed Rhongomyniad (GPU) Sersic deflection matches a scipy@1e-12 integral to about 1e-9 arcsec, while glafic's Sersic is Romberg-tolerance-limited (TOL_ROMBERG_JHK, kept at 1e-5 here: fast but not accurate enough at roughly micro-arcsec to milli-arcsec scales). Verification now reports both the glafic binary (informational) and the scipy-exact reference (run-engine Sersic deflection error plus source-plane self-consistency). Saved results now use 10 significant figures.

V0.4.0 - ReUnit Major Update

- Core refactor: the previously scattered and duplicated Differential Evolution optimization and plotting code in legacy/ was extracted into a unified, backend-agnostic core/ module. legacy/ remains as a historical archive, while new code no longer depends on it.
  - core/optimize: a single DE optimizer can drive glafic (CPU) or Rhongomyniad (GPU); main lenses and substructures (point-mass / NFW / King / p-jaffe and more) can be composed and optimized together.
  - core/plot: unified triptych, critical-curve, and iteration-frame plotting.
  - core/format: a new .dat configuration format and parser.
  - core/translate: bidirectional glafic <-> GLADE translation scripts, including a CLI.
- New .dat configuration format: close to the legacy inline style, with {lower, upper} marking optimizable dimensions (bare values are locked) and $float / $int as fill-in placeholders; mass-like parameters are searched in log10 space. Multiple files merge by section, component indices are globally renumbered, and missing basic values fall back to defaults with confirmation.
- Fully rewritten WebUI (webui/; old web/ deprecated): top-level FindImage and Editor pages; FindImage selects CPU / GPU / Glafic plus one or more .dat files, opens a real terminal for each run, and streams output back through SSE into independent job directories to solve concurrency issues. The Editor is VSCode-like with a 50px icon rail, draggable sidebar, Monaco multi-tab editor, save/delete controls, Explorer management for InputFiles, import/export translation, and Template insertion at the cursor.
- glafic <-> GLADE translation: import converts optimization-matrix parameters marked as 1 into {v, v} bounds for manual adjustment; export writes representative values for bounds (geometric mean for mass-like parameters) and separates observation/model data.
- Fixes: center_offset_x in the DE objective now follows obs_x_flip so it stays in the same coordinate system as observations, fixing global predicted-image offsets and stuck losses; glafic TOL_ROMBERG_JHK is set to 1.0e-5 as a speed/accuracy compromise.
